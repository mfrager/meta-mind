## 1. Library organization

```
frontend/src/components/
├── ui/        # shadcn primitives (generated by components.json workflow) — never hand-styled beyond tokens
├── blocks/    # shadcn blocks adapted (app shell, dashboards, cards, settings) — page templates
├── kit/       # our custom rich components (§4) — the visible design language
├── trees/     # TreeCore + domain trees (06)
├── mindmap/   # mind-map engines (07)
├── chat/      # chat components (08)
├── docs/      # document viewers/editors (05)
└── charts/    # chart recipes bound to tokens (§4.6)
```

**Rules of the library**

1. **Tokens only.** No literal colors, radii, or shadows in components; every visual comes from `02`.
2. **Every component ships its states**: default / hover / active / focus / disabled / loading / empty /
   error — listed in its catalog page and asserted in unit tests (§5).
3. **Variants via CVA** (`class-variance-authority`) with semantic names (`tone="knowledge"`,
   `size="sm|md"`, `emphasis="quiet|outline|solid"`), never ad-hoc class soup at call sites.
4. **One concept, one component.** If two screens need "a title with a kind icon and status chips", it is
   `DocTitle`, not two div trees.
5. Composition over configuration: components accept `slots`/`children` for extension instead of a
   growing prop surface.

## 4. The kit layer (custom rich components)

Each entry: purpose, key variants, and the states it must ship. Props are normative TypeScript sketches.

### 4.1 `IconChip`
The signature kind marker (see `02` §7).
```ts
type IconChipKind = 'doc'|'chart'|'log'|'tree'|'mindmap'|'diff'|'proof'|'run'|'memory'|'claim'|'goal'|'module'|'tool'|'budget'|'policy'|'frame'|'skill'|'case'|'decision'|'episode';
IconChip({ kind, size?: 12|14|16|20, tone?, spin?: boolean })
```
States: static, spin (running), dimmed (unavailable), overlaid (badge corner for counts).

### 4.2 `KindBadge`
Icon chip + micro-label name ("CHANGE SET", "RUN LOG") in the kind's tone. Used in doc headers, tabs,
tree rows, chat chips.

### 4.3 Cards (the core container family)

`Card` base (2px radius, 1px border, opaque) with composable parts: `CardHeader` (tinted 4% of tone),
`CardTitle` (H2 + optional icon chip + micro-label eyebrow), `CardActions` (right-aligned icon buttons),
`CardBody`, `CardFooter` (actions + provenance strip), `CardRail` (3px left accent in tone).

| Variant | Anatomy | Use |
|---|---|---|
| `StatCard` | micro-label · value (mono 20px) · delta chip · sparkline · footnote | Overview grids, budget summaries |
| `MeterCard` | title · `GaugeArc` or linear meter · threshold labels · breakdown row | Budgets, risk, coverage |
| `ChartCard` | header w/ range+series toggles · chart · legend · footnote · export menu | Chart documents, chat chart blocks |
| `TableCard` | toolbar (search/filter/columns) · table · footer (count, pagination) | Any record set |
| `ListCard` | header · scroll list of `ListRow` (icon chip · title · value · spark) | Recent activity, memory hits |
| `FeedCard` | header · timeline rows (time gutter · icon · text) | Event feed, run stages |
| `ProseCard` | title · markdown body (14/22) · epistemic badges | Notes, design docs, summaries |
| `CodeCard` | language chip · `CodeBlock` · copy/download | SEM, Turtle, JSON, diffs |
| `VerdictCard` | big verdict chip · reason · evidence list · actions | Firewall, promotion, verify results |
| `ProofCard` | goal line · numbered proof steps (expandable) · QED chip | `verify run` outputs |
| `ScreenshotCard` | framed screenshot (2px) · caption · zoom | Chart PNG exports, audit captures |

States for all cards: `loading` (skeleton rows), `empty` (quiet icon + sentence + action), `error`
(`ErrorState` inline), `stale` (amber corner ribbon + refresh), `live` (pulsing dot in header).

### 4.4 Tabs (five variants — variety without novelty)

| Variant | Look | Use |
|---|---|---|
| `underline` (default) | text tabs, 2px azure underline on active, 1px baseline | Doc sub-views (Summary / Data / Raw) |
| `segmented` | joined control, active segment `bg-card` + E1 + 4px radius | Mode switches (View/Edit/Diff/Raw) |
| `pill-row` | pill chips with icon chips + counts | Filter tabs (All / Failed / Promoted) |
| `vertical` | left rail tabs with icon chips + 2px azure left rail | Doc pane side tabs (Outline / Details) |
| `pane-tabs` | dense tabs with kind icon chip + dirty dot + close × | Document/chat tab strips (`03` §3) |

Behavior: roving tabindex, `?` optional lazy panels, overflow scroll with edge fades (never hamburger
wrapping inside panes), keyboard `←/→` move + activate.

### 4.5 Accordions (three variants)

| Variant | Look | Use |
|---|---|---|
| `panel` | boxed sections, header row 32px + chevron + count badge, 2px radius | Detail documents, settings |
| `flush` | bordered list, top/bottom hairlines only | Chat op detail groups, log groups |
| `faq` | bold question + quiet answer, no box | Empty states, help, guided tours |

Behavior: single/multi expand, `defaultOpen` per id, URL-sync option (`?section=`), animated height
(`--t-base`, disabled on reduced motion), header micro-label + right-aligned meta (count, chip).

### 4.6 Carousels (three variants, embla)

| Variant | Look | Use |
|---|---|---|
| `CardCarousel` | 260px cards, peek 24px of next, dot + arrow controls below-right | Recent documents, suggested runs, gallery of chart snapshots |
| `StepCarousel` | numbered steps with a progress rail on top, content card below | Guided tours (the user guide's five-minute tour), promotion wizard |
| `ScreenshotCarousel` | full-width frame, filmstrip thumbnails, zoom-in-lightbox | Run artifact galleries, audit captures |

Behavior: drag + wheel, snap, keyboard, `aria-roledescription="carousel"`, lazy image loading,
`onFocusIndexChange` hooks for captions.

### 4.7 Forms

The form system is the shadcn `form` (react-hook-form + zod resolvers) with these **recipes**:

| Recipe | Anatomy | Use |
|---|---|---|
| `FilterForm` | inline row of selects/inputs + clear + count chip | Table/log filtering (debounced live) |
| `RecordForm` | labeled fields in 2-col grid, sections via `panel` accordions, sticky footer (Save draft / Cancel) | Document editors (`05` §5) |
| `CommandForm` | fields generated from a command's arg schema, `--json` preview pane, Run button | Palette arg forms, `/command` chat forms (`08` §5.5) |
| `WizardForm` | `StepCarousel` + per-step validation + step completion chips | `changeset new` → sandbox → promote flow |
| `SettingsForm` | sections + dirty tracking + "changed N fields" chip + reason field for writes | `/settings` |
| `InlineEdit` | click-to-edit field (label → input), Enter/ESC, optimistic save | Tree renames, doc titles |

Field kit (all with label, micro-help, error text, required `*`, disabled reason tooltip):
`TextField`, `TextAreaField` (mono option), `NumberField` (stepper + unit suffix), `SelectField`,
`ComboboxField` (searchable, multi option), `CheckboxField`, `SwitchField`, `RadioField` (card-style
radio rows), `SliderField`, `DateField`, `TagsField` (TagInput), `JsonField` (Monaco mini),
`SemField` (SEM editor with live indent + highlight), `LatexField` (KaTeX preview), `FileField`,
`ImageField` (the image chooser, `08` §5.4), `ButtonGridField` (button grid as a form control, `08` §5.3).

Validation: zod schemas shared with `mm-serve` command arg schemas where possible (schema-derived
`CommandForm`); errors summarize in a banner at submit + per-field; every form documents its
keyboard behavior (Tab order, Enter-to-submit only in single-line fields).

### 4.8 Feedback and status components

| Component | Spec |
|---|---|
| `StatusChip` | The §3.2 chip family; `tone` + `icon` + `label` + optional `reason` tooltip; sizes 18/22px |
| `Banner` | Page-level strip (info/amber/red/positive), icon + text + actions + dismiss (sticky until dismissed if `severity=error`) |
| `Toast` (sonner) | Positions bottom-right; promise toasts for async ops; action button; never used for state that must stay visible (banners/cards instead) |
| `InlineNote` | Quiet paragraph with icon chip (tip/note/warning), used in forms and empty states |
| `ProgressBar` | Determinate (mono % right) and indeterminate (3-segment sweep); tones per §3.2 |
| `StageTicker` | N segments (e.g. 10 loop stages), done=green, active=violet pulsing, failed=red, pending=muted; hover shows stage names; used in status bar + run docs |
| `Sparkline` | See `02` §6 |
| `GaugeArc` | 270° arc gauge with threshold bands |
| `Delta` | `▲ 4.2%` / `▼ 1.1%` mono chip, green/red semantic, neutral slate for no-change |

### 4.9 Overlays

`Dialog` (E2, 6px), `AlertDialog` (destructive confirmations always name the object and require typing
its id for irreversible ops like `gc --apply`), `Drawer` (right, 480px, for detail peeks — the "peek"
behind `View lineage`), `Popover` (E1), `Lightbox` (image zoom with filmstrip), `CommandPalette` (`03` §5).
All overlays: `Esc` closes, focus restored, backdrop 24% `--foreground` scrim, no blur except palette.

### 4.10 Tables

`DataTable` recipe: toolbar (search `SearchInput`, `FilterForm` popover, column visibility menu, density,
export), sticky header (micro-labels, sortable with chevrons), row height per density, row selection with
tri-state header checkbox, row actions menu, footer (count + pagination), **row expansion** to an
inline detail region, column types (`text`, `mono-value`, `chip`, `spark`, `time`, `actions`) each with
token styling. Virtualized variant (`VirtualTable`) for logs (`05` §8) reuses the same column spec.

### 4.11 Composition helpers

- `SectionHeader` (micro-label + rule + actions) — replaces "a div with bold text".
- `KeyValueGrid` (dt/dd pairs in 2-col mono-right grid — the rust_symbolic tool-input `dl`, promoted to a
  library component).
- `Toolbar` (icon button groups with separators, overflow to `MoreMenu`).
- `SplitDetail` (list-left / detail-right mini layout used inside documents).
- `EmptyState`, `ErrorState`, `LoadingState` (§4.12).

### 4.12 Empty / error / loading patterns

- `EmptyState`: 8%-opacity isometric art (one of 6 variants), one sentence, one `Button`, up to two
  quiet links, optional `Accordion` "What is this?" explanation.
- `ErrorState`: red icon chip, `message` (H3), kernel `reason` in a mono block, actions (Retry / Open
  logs / Copy details), correlation id footnote.
- `LoadingState`: skeleton recipes matched to the real layout (never spinners alone for content areas),
  shimmer at 1.2s (static under reduced motion).

## 5. The catalog (`/dev/catalog`)

- Route reachable in every build (tree-shaken out of production bundles by a flag).
- Sections mirror this document; every component shows **all variants × all states** side by side with a
  props table and a "Copy JSX" button.
- **Token inspector**: hover any element to see its token recipe (dev overlay).
- **Radius gallery** (§`02` §5.3): the allowed shapes, pinned, with visual-diff protection.
- Unit tests (vitest + RTL) iterate the catalog registry and assert render + a11y (axe) for each entry;
  Playwright screenshots the catalog for visual regression (`10` §6.4).

## 6. Graphical richness budget (how much is too much)

Rich graphics are **concentrated where information lives** (charts, trees, maps, meters, dashboards) and
absent where it does not (settings forms, dialogs, plain lists). Concretely: any screen may have at most
**one** hero graphic region; cards may have at most one sparkline *or* one gauge *or* one meter each;
gradients appear only in chart fills and empty-state art. This keeps "colorful and graphically rich"
from becoming "over-done" (design principle 10 in `00` §4).
