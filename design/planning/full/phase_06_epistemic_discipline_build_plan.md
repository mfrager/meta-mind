# Phase 6 — Epistemic Discipline (Extended Build Plan)

> Extended from: `design/planning/phase_06_epistemic_discipline_build_plan.md` · Parent plan: `design/planning/implementation_plan1.md` §13 Phase 6 · Codename Metamind (`mm`)

This revision keeps the scope and gate of the Phase 6 plan but locks in the concrete mechanisms a review
of available code suggests: a status lattice with a deterministic promotion guard, a **justification
graph** with dependency-directed retraction, explicit contradiction records augmented by ASP/SMT
consistency checks when a fragment is formalizable, and PROV-O/RDF-star provenance for every claim change.

## 1. Objective and scope

Make it structurally impossible to confuse **what the being thinks** with **what the world contains**:
typed epistemic objects with explicit status, an assumption ledger with deterministic verification
priority, explicit contradiction records, a justification graph whose invalidation cascades, and a
deterministic validation barrier before any commit.

> **Rule:** no silent promotion. A proposition's status may only rise by evidence that satisfies a
> deterministic transition table; only `OBSERVED`/`VERIFIED` may enter the `/world` graph.

**In scope:** `mm-epistemic` crate (statuses, claims/evidence/observations/inferences/assumptions/
predictions, contradiction detection, justification graph, validation barrier); the `/world` vs
`/epistemic` graph separation; PROV-O/RDF-star provenance; one nexus module (`epistemic-ops`); SQLite
persistence, logging, and the golden/adversarial fixtures.

**Out of scope:** the metacognitive program compiler (Phase 8); the sanity *firewall* outcome enum and
Jev decisions (Phase 9); causal counterfactual computation (Phase 11); learned calibration thresholds
(Phase 11).

## 2. Architecture and invariants

```
                     candidate claim + evidence (from LLM / tools)
                                     │
                             ValidationBarrier  ── SHACL + RDFUnit data tests (+ ASP/SMT if formal)
                                     │ reject ⇒ hard error, logged
                                     ▼
   ┌──────────── EpistemicEngine (async) ─────────────────────────────────────────┐
   │  status lattice + PromotionGuard        justification graph (JTMS-style)     │
   │  assumption ledger (priority)           ContradictionDetector (+ ASP/SMT)    │
   └───────────────┬──────────────────────────────────────────────┬──────────────┘
                   │ append→apply→commit (Phase 1 protocol)        │
                   ▼                                               ▼
          /epistemic graph                                 /world graph
          all statuses + provenance (PROV-O/RDF-star)      ONLY Observed|Verified
                   │                                               │
                   └───────────────► mm-log audit ◄────────────────┘
```

**Invariants**

1. **Status lattice is monotone-guarded.** `can_promote(from, to, evidence)` is pure and takes no model
   output; the forbidden promotions are impossible regardless of evidence.
2. **One way into `/world`.** The `ValidationBarrier` is the only writer permitted to touch `/world`, and
   it admits only `OBSERVED`/`VERIFIED` claims with evidence.
3. **Justifications are explicit.** Every derived belief names the assumptions/claims it depends on
   (ATMS-style in-list); retraction removes the whole support set at once (dependency-directed).
4. **Contradictions are objects, never silent edits.** A conflict is an explicit `mm:Contradiction` with
   both sides and evidence; reconciliation is a later, logged action.
5. **Provenance is complete.** Every claim change carries PROV-O activity/agent plus an RDF-star
   annotation of the prior value.
6. **Determinism.** The priority/budget arithmetic is fixed `f64`, golden-tested; probabilities enter
   from the caller, never computed here.

## 4. Detailed specifications

### 4.1 Core types

```rust
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum EpistemicStatus { Observed, Verified, Reported, Inferred, Assumed,
                           Hypothetical, Predicted, Simulated, Fictional, Unknown }

#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Debug)]
pub enum RiskLevel { Negligible, Low, Medium, High, Catastrophic }

pub struct Proposition { pub subject: NamedNode, pub predicate: NamedNode, pub object: Term }
pub enum ClaimKind { Fact, Observation, Inference, Hypothesis, Prediction, Simulation, Fiction }

pub struct Claim {
    pub id: Ulid, pub kind: ClaimKind, pub proposition: Proposition,
    pub status: EpistemicStatus, pub confidence: f32,
    pub evidence: Vec<Ulid>, pub valid_from: Option<Timestamp>, pub valid_until: Option<Timestamp>,
}
pub struct Evidence { pub id: Ulid, pub kind: EvidenceKind, pub source_uri: Option<NamedNode>,
                      pub span: Option<(u32, u32)>, pub content_hash: [u8; 32], pub reliability: f32 }

pub struct Assumption {
    pub id: Ulid, pub proposition: Proposition, pub status: EpistemicStatus, pub confidence: f32,
    pub consequence_if_false: RiskLevel, pub verification_cost: f64,
    pub decision_dependence: f64, pub dependencies: Vec<Ulid>,
}
pub fn verification_priority(a: &Assumption, p_false: f64) -> f64;
pub fn epistemic_budget(p_false: f64, error_cost: f64, uncertainty: f64, verification_cost: f64) -> f64;

/// Deterministic. Takes NO model output.
pub struct PromotionDenied { pub from: EpistemicStatus, pub to: EpistemicStatus, pub reason: &'static str }
pub fn can_promote(from: EpistemicStatus, to: EpistemicStatus, ev: &[Evidence]) -> Result<(), PromotionDenied>;
```

**Transition table (excerpt).** Forbidden unconditionally: `Assumed→{Observed,Verified}`,
`Inferred→Observed`, `Predicted→Observed`, `Simulated→Verified`, `Fictional→*`, `Unknown→*`.
`Reported→Inferred` requires ≥1 evidence; `Inferred→Verified` requires authoritative evidence
(`EvidenceKind::ExternalTool`); `Observed` may never be rewritten, only superseded by a new claim.

### 4.2 Justification graph (JTMS/ATMS-inspired)

```rust
pub enum DepKind { Assumption, Derivation, Observation, Prediction, Decision }

pub struct Justification { pub consequent: Ulid, pub antecedents: Vec<Ulid>, pub kind: DepKind,
                           pub criticality: f32 }        // in-list; out-list is empty by construction

pub struct JustificationGraph { /* adjacency + reverse index */ }
impl JustificationGraph {
    pub fn add(&mut self, j: Justification) -> Result<(), EpistemicError>;   // rejects cycles
    pub fn is_acyclic(&self) -> bool;
    pub fn transitive_dependents(&self, root: Ulid) -> Vec<Ulid>;            // dependency-directed retraction
    pub fn why(&self, node: Ulid) -> Vec<Justification>;                     // why-provenance walk
}
```

`cascade_invalidate(root)` marks every transitive dependent `Unknown`/suspect in one deterministic pass,
emitting one event per affected node and one PROV-star annotation per status change.

### 4.3 Contradiction detection

```rust
pub enum ContradictionStatus { Open, Mitigated, Resolved, Dismissed }
pub struct Contradiction { pub id: Ulid, pub claim_a: Ulid, pub claim_b: Ulid,
                           pub reason: String, pub evidence_a: Option<Ulid>, pub evidence_b: Option<Ulid>,
                           pub status: ContradictionStatus }
pub trait ContradictionDetector { fn check(&self, new: &Claim, existing: &[Claim]) -> Vec<Contradiction>; }
```

Indexed by `(subject, predicate)` buckets so only comparable candidates are tested (avoids O(n²)).
When a claim set is **formalizable** (linear arithmetic / propositional constraints), the detector also
asks the copied ASP/SMT backends (`clingo`/`Z3` via the Phase 9 seam) for a stable model; no model ⇒
contradiction. A conflict sets both claims `Reported`/`Uncertain`, writes an explicit record, and **never**
reconciles silently.

### 4.4 PROV-O + RDF-star emission (`prov.rs`)

Each claim writes, in `/provenance`:

```turtle
@prefix prov: <http://www.w3.org/ns/prov#> .
@prefix mm:   <https://metamind.dev/ontology#> .
@prefix mmd:  <https://metamind.dev/data/> .

mmd:{claim} a mm:Claim, prov:Entity ;
    prov:wasGeneratedBy  mmd:{verification-activity} ;
    prov:wasDerivedFrom  mmd:{source-claim-or-evidence} ;
    prov:wasAttributedTo mmd:{source-agent} ;
    mm:status "INFERRED" ; mm:confidence 0.72 .

# RDF-star (RDF 1.2) change annotation — PROV-STAR idea
<< mmd:{claim} mm:status "REPORTED" >> prov:wasGeneratedBy mmd:{status-change} ;
    prov:startedAtTime "2026-10-08T10:00:00Z"^^xsd:dateTime .
```

### 4.5 SQLite — `migrations/0006_epistemic.sql`

All ids `TEXT(26)` (ULID); times RFC3339 ns. Every table carries `system_from`/`system_to` for replay.

```sql
CREATE TABLE claims (
  id TEXT(26) PRIMARY KEY, kind TEXT NOT NULL,
  subject TEXT NOT NULL, predicate TEXT NOT NULL, object TEXT NOT NULL,
  status TEXT NOT NULL, confidence REAL NOT NULL CHECK (confidence BETWEEN 0 AND 1),
  valid_from TEXT, valid_until TEXT, source_ulid TEXT,
  system_from TEXT NOT NULL, system_to TEXT, created_ulid TEXT NOT NULL
);
CREATE TABLE evidence (
  id TEXT(26) PRIMARY KEY, claim_id TEXT(26) NOT NULL REFERENCES claims(id),
  kind TEXT NOT NULL, source_uri TEXT, span_start INTEGER, span_end INTEGER,
  content_hash TEXT NOT NULL, reliability REAL NOT NULL, created_ulid TEXT NOT NULL
);
CREATE TABLE observations (
  id TEXT(26) PRIMARY KEY, claim_id TEXT(26) NOT NULL REFERENCES claims(id),
  authoritative INTEGER NOT NULL, observed_at TEXT NOT NULL,
  source_ulid TEXT NOT NULL, created_ulid TEXT NOT NULL
);
CREATE TABLE assumptions (
  id TEXT(26) PRIMARY KEY, proposition_uri TEXT NOT NULL, status TEXT NOT NULL,
  confidence REAL NOT NULL, consequence_if_false TEXT NOT NULL,
  verification_cost REAL NOT NULL, decision_dependence REAL NOT NULL,
  valid_from TEXT, valid_until TEXT, created_ulid TEXT NOT NULL
);
CREATE TABLE predictions (
  id TEXT(26) PRIMARY KEY, proposition_uri TEXT NOT NULL, probability REAL NOT NULL,
  horizon_secs INTEGER NOT NULL, conditions_json TEXT NOT NULL, created_ulid TEXT NOT NULL,
  outcome_status TEXT, outcome_value TEXT, resolved_at TEXT
);
CREATE TABLE contradictions (
  id TEXT(26) PRIMARY KEY, claim_a TEXT(26) NOT NULL, claim_b TEXT(26) NOT NULL,
  reason TEXT NOT NULL, evidence_a TEXT, evidence_b TEXT, status TEXT NOT NULL,
  created_ulid TEXT NOT NULL
);
CREATE TABLE dependencies (
  id TEXT(26) PRIMARY KEY, consequent TEXT(26) NOT NULL, antecedent TEXT(26) NOT NULL,
  kind TEXT NOT NULL, criticality REAL NOT NULL, created_ulid TEXT NOT NULL,
  UNIQUE(consequent, antecedent)
);
CREATE TABLE epistemic_transitions (
  id TEXT(26) PRIMARY KEY, subject TEXT NOT NULL, from_status TEXT, to_status TEXT,
  reason TEXT NOT NULL, evidence_ulid TEXT, prov_activity TEXT, created_ulid TEXT NOT NULL
);
CREATE INDEX idx_claims_spo  ON claims(subject, predicate, object);
CREATE INDEX idx_deps_ante  ON dependencies(antecedent);
CREATE INDEX idx_claims_asof ON claims(subject, predicate, system_from, valid_from);
```

### 4.6 Ontology and shapes

- **Classes:** `mm:Claim, mm:Observation, mm:Inference, mm:Hypothesis, mm:Assumption, mm:Prediction,
  mm:Evidence, mm:Contradiction, mm:Dependency, mm:Justification`.
- **Properties:** `mm:status, mm:confidence, mm:evidenceFor, mm:supports, mm:contradicts, mm:derivedFrom,
  mm:dependsOn, mm:observedAt, mm:validFrom, mm:validUntil, mm:consequenceIfFalse, mm:verificationCost,
  mm:decisionDependence, mm:source`; PROV-O reused verbatim.
- **Named graphs:** `.../graph/epistemic` (all epistemic objects) and `.../graph/world` (only
  `OBSERVED`/`VERIFIED`), plus `.../graph/provenance` (PROV-O + RDF-star).
- `ontology/shapes/epistemic_shapes.ttl` enforces: exactly one `mm:status` and one `mm:confidence` in
  `[0,1]` per claim; every `mm:Assumption` has `consequenceIfFalse`, `verificationCost`,
  `decisionDependence`; `mm:Dependency` is non-self-referential; `/world` members are `OBSERVED|VERIFIED`.

## 9. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Over-modeling epistemic machinery the LLM could supply | Keep the layer to typed status + guard + ledger + justification graph (design §108) |
| Status inflation (everything becomes `VERIFIED`) | Promotion requires evidence satisfying `can_promote`; `/world` writer is the only path and is audited |
| Pairwise contradiction detection is O(n²) | Index by `(subject, predicate)`; only comparable candidates are tested |
| ASP/SMT cost on large graphs | Only formalizable fragments are sent to the solver; budget-capped, deterministic timeout |
| RDF-star not universally supported | Underlying store is Oxigraph (RDF 1.2); a plain-reification fallback is emitted when a reader lacks RDF-star |
| Contradiction spam / false positives | Contradictions carry status; materiality is scored in Phase 9, not here |
| World/epistemic leakage | Named-graph separation + `world_separation.rs` + audited single writer |
| Nondeterminism from float priority | Fixed formula, `f64`, golden CSV with tolerance; no model input |
| Cascade performance at scale | Graph stored once; transitive set computed iteratively, one event per node |
