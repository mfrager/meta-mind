# 04 — The simplified console

> Parent: [`INDEX.md`](./INDEX.md) · Previous: [`03_middleware.md`](./03_middleware.md) · Next: [`05_phases.md`](./05_phases.md)

The operator chats with the controller. The other pane shows the being's state, or the one document
the controller has focused. Everything else moves out of the default path.

The styling law in `design/planning/ui/02_design_system.md` still applies: semantic color, small radii,
tokens only, no invented metrics.

---

## 1. The default screen

```text
┌ top bar: Metamind · session title · kernel dot ─────────────────┐
├────────────────────────────┬────────────────────────────────────┤
│ State or document          │ Controller                         │
│                            │  intro, then the transcript        │
│  (one of the two, never    │  tool cards under the turn         │
│   a third mode)            │  composer                          │
│                            │                                    │
├ status: kernel · events · model name · data dir ───────────────┤
└────────────────────────────────────────────────────────────────┘
```

Chat is on the right on wide and medium widths, and is the first tab on narrow and monitor widths.
The split starts at 42% state / 58% chat. The chat pane cannot be collapsed on the default route.
The state/document pane can collapse to a thin rail labeled "State" or the document title; expanding
it does not change the conversation.

There is no sidebar of documents, trees, and maps on this route. Those entries were a catalog of
things the operator was expected to open by hand. The controller opens them.

## 2. What leaves the default route

| Today | After phase 3 |
|---|---|
| Left nav of every document in `frontend/src/lib/nav.ts` | Removed from the default shell. `/dev/catalog` and `/settings` stay, linked from a single "More" menu in the top bar. |
| Command palette of 42 CLI names that runs chat queries | Removed as an executor. Ctrl/⌘K focuses the composer. A palette may search the current transcript and the guide chapters, and inserting a chapter is just text in the composer, not a tool call. |
| Slash commands that classify to a subcommand | The composer does not treat `/` as a command. A leading `/` is ordinary text. |
| Suggestion chips of command names | The three server chips in `01` §4.3, then whatever the controller sends. No client-side command list. |
| Status bar "llm cache unavailable" | The model names from the health reason when `llm` is `ok` (`model=…`), or `llm unavailable` when it is not. Already the direction of `statusbar.tsx`; phase 3 makes that the only LLM chip. |
| Map route `/map/:source` as a primary nav item | Still a document kind. It opens when a tool focuses a map id. No map button in the shell. |
| Fixture banners and empty reasons | Unchanged. A focused fixture still says it is a fixture. |

`/dev/catalog` keeps the component gallery for people building the UI. It is not part of using
Metamind. The pass-gate tests that count catalog entries stay on that route and are not deleted.

## 3. The state board

Shown whenever the focus id is `state` or nothing has been focused. It is a column of live sections,
each a card, each allowed to be empty.

1. **Kernel.** State, and any service that is not `ok`, with that service's reason. Services that are
   `ok` are a single line "sqlite, event log, graph, llm" plus the llm reason's model list. No sparkline.
2. **Being.** `self_description`, version, the four invariant codes, goal count, and the projected chat
   voice as five small numbers. If the being store failed, this card is the boot error and nothing else.
3. **Goals.** The goal list from `being.goal_list`, or "No goals are recorded." A goal row is text and
   priority. Clicking a row does not edit it. The operator asks the controller.
4. **Budgets.** The four real rows (`meta_analysis`, `improvement`, `evolution`, `metacognitive`). The
   same component the budgets document uses. No fifth meter.
5. **Last action.** The last tool result in this session: name, ok, summary. Empty until the first tool.

The board refetches on a `focus` frame with id `state`, on a successful `being.*` or `budget.show`
tool, and on the health poll the shell already runs. It does not poll the being store on its own
timer.

Components: `frontend/src/components/state/state-board.tsx` composed from existing cards
(`stat-card`, `list-card`, `status-chip`). No new visual language.

## 4. The document pane

The current focus viewers stay (`frontend/src/components/docs/viewers.tsx` and the tree editors).
What changes is *who navigates*.

- The pane's header is the document title, kind, and status. A text button "Back to state" calls
  `focus.open` equivalent on the client only: it sets the local focus id to `state`. It does not tell
  the model unless the next user message is sent, at which point ContextMw reports the state board
  again. The operator can look away without a turn.
- There is no document picker, no tree of all docs, no "open budgets" button. If the operator wants
  the budget document, they ask. The controller calls `budget.show`, FocusMw emits `focus`, the pane
  swaps from the state board to that document.
- Edits in the pane are disabled in phase 3 (viewers only). Phase 4 enables editors for kinds
  `focus.patch` maps, and every edit is a tool call the controller makes, which means a confirmation
  when the tool says so. The operator does not get a second save path that writes the store behind
  the controller's back. Inline edit widgets that today would write locally become read-only until
  phase 4, then they send `focus.patch` and wait for the tool result before showing the new value.
- A fixture document keeps its fixture sentence. The controller can focus it to explain that the live
  data is not on that route. It cannot patch it (`02` §3.4).

The document pane and the state board are the two children of one slot, `SidePane`, in
`frontend/src/routes/workspace.tsx`. `WorkspaceSplit` still receives `document` and `chat`. The
`document` slot is `SidePane`. Chat is `ControllerPane`.

## 5. The controller pane

Reuse `frontend/src/components/chat/`:

| Piece | Change |
|---|---|
| `chat-header.tsx` | Title is the session title. Subline is "Metamind", not a provider advertisement. A chip shows `high_stakes` only when the current turn has that tag. |
| `transcript-view.tsx` | Renders the intro as a normal assistant bubble. Tool cards stay. The unbacked chip is a `status-chip` on the bubble. |
| `composer.tsx` | Placeholder "Ask Metamind…". Enter is still newline. ⌘/Ctrl+Enter sends. No slash menu. |
| `op-registry.tsx` | One generic tool card for every controller tool: name, ok/failed, summary, expandable `data`. Specialized cards remain for `decide.ask`, `budget.show`, and `promote.run` because those payloads already have renderers. New tools use the generic card until a later plan. |
| `input-request.tsx` | Approve / Reject / Defer, unchanged. The title is the tool name. |

The pane does not show a phase rail of PLAN / VERIFY unless a tool result is a real stage list from
`loop.status`. A controller round is not a metacognitive stage. Labeling it as one would invent a run.

Empty composer help is nothing. The intro already said how to start. A pulsing hint is not added.

## 6. Top bar and status bar

Top bar, left to right: wordmark "Metamind", the session title (click to rename), a kernel dot with
the same tooltip as today (services that are not `ok`). Right side: theme, density, "More"
(Settings, Catalog). Delete the view menu items that swap panes as a primary gesture; the split
handle remains. "Local operator" stays, because the console is still single-user.

Status bar, left to right: kernel label, event head, the llm chip (`04` §2), the data directory's
base name. Drop the decorative budget ticks that are not wired to the four rows. Budgets live on the
state board, where they are real.

## 7. Routes

| Path | Screen |
|---|---|
| `/` and `/chat/:sessionId` | The screen in §1. `/` creates or resumes the latest session. |
| `/settings` | Unchanged. |
| `/dev/catalog` | Unchanged, reached from More. |
| `/map/:source` | Redirect to `/?doc=` only when a focus id is a map; otherwise the map renders inside `SidePane` when focused, and the route remains for a direct link. Direct links still work. They are not in the nav. |

No new route for the controller. It is the index.

## 8. Accessibility and motion

One heading on the default screen: the session title, `h1`, visually the header text. The state board's
section titles are `h2`. The transcript is a log with `aria-live="polite"` on the last assistant
bubble only, so a tool-heavy turn does not announce every JSON line. Tool cards are disclosures.

Confirm buttons are real buttons in the transcript, in tab order after the composer only when a
request is waiting; otherwise the composer is the first stop. Esc while a confirm is focused does not
reject it. Rejection is the Reject button. Esc still closes dialogs that are dialogs.

Reduced motion and the print rules from the UI plan stay. Print hides the composer and shows the
transcript and the side pane.

## 9. What the operator can do without learning a command

These are the acceptance stories for phase 3, each starting from a fresh session:

1. Read the intro and know what to type.
2. Ask "how do I use this?" and get an answer from `guide.read start`, short, in the being's voice.
3. Ask "show me your state" and see the state board update, not a new chat-only JSON blob.
4. Ask "what are the budgets?" and see the budget document replace the state board, with the four
   seeded names.
5. Ask "go back" and see the state board again because the controller called `state.show`.
6. Have no way, on this screen, to invoke `promote` except by asking and then pressing Approve.
