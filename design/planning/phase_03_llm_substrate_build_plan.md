# Phase 3 Build Plan — LLM cognitive substrate

> Parent plan: `design/planning/implementation_plan1.md` §13 Phase 3 · Codename Metamind (`mm`)

## 1. Objective and scope

Deliver **one typed, cached, accountable LLM interface** (`mm-llm`) that every cognitive component uses.
No component may call a provider directly; all inference flows through `mm-llm`, which guarantees that
each call is schema-validated, budgeted, provenance-recorded, logged, and reproducible offline.

In scope:

- A provider-neutral async client adapter over the copied `kg-llm` reference (`LlmClient`, mock, cached,
  OpenAI-compatible, structured output, request hashing).
- Hard structured-output validation (reject, never coerce) with repair-attempt recording.
- Deterministic **request-hash cache** and a **replay mode** that performs zero provider calls.
- Accounting (`CallAccount`) and SQLite accounting tables; provenance mirror to `/provenance`.
- Deterministic **routing** behind a `Router` trait, with the explicit `DecisionCore` seam for Phase 9.
- `mm-cli llm` operator commands and an adversarial fixture corpus.

Out of scope: the metacognitive controller and program compiler (Phase 8); `DecisionCore`
implementations and calibration (Phase 9); any being/memory semantics (Phases 4–5). Phase 3 supplies the
interface those phases consume, not their logic.

  `sqlx` (sqlite), `tracing`, plus the vendored `kg-llm` crates.

## 4. Data model and ontology deltas

### SQLite (migration `0003_llm.sql`)

```sql
CREATE TABLE llm_calls (
  id            TEXT(26) PRIMARY KEY,      -- ULID
  trace_id      TEXT(26),                  -- correlation ULID (episode / action / span)
  purpose       TEXT NOT NULL,             -- interpret|plan|extract|critique|summarize|code_review|classify|diagnose
  provider      TEXT NOT NULL,
  model         TEXT NOT NULL,
  prompt_hash   TEXT NOT NULL,             -- sha256 over canonical request
  schema_id     TEXT,                      -- None => free-text call
  schema_ok     INTEGER NOT NULL DEFAULT 1,
  routed_from   TEXT,                      -- requested model (if routing changed it)
  route_reason  TEXT,
  cached        INTEGER NOT NULL DEFAULT 0,
  tokens_in     INTEGER NOT NULL DEFAULT 0,
  tokens_out    INTEGER NOT NULL DEFAULT 0,
  cost_micros   INTEGER NOT NULL DEFAULT 0,
  latency_ms    INTEGER NOT NULL DEFAULT 0,
  status        TEXT NOT NULL,             -- ok|schema_rejected|provider_error|timeout|replay
  error_kind    TEXT,
  created_ulid  TEXT(26) NOT NULL,
  created_at    TEXT NOT NULL              -- RFC 3339 UTC
);
CREATE INDEX idx_llm_calls_purpose     ON llm_calls(purpose);
CREATE INDEX idx_llm_calls_prompt_hash ON llm_calls(prompt_hash);
CREATE INDEX idx_llm_calls_trace       ON llm_calls(trace_id);

CREATE TABLE llm_cache_index (
  prompt_hash   TEXT PRIMARY KEY,
  model         TEXT NOT NULL,
  schema_id     TEXT,
  response_path TEXT NOT NULL,             -- data/llm_cache/<prompt_hash>.json
  response_sha  TEXT NOT NULL,
  created_ulid  TEXT(26) NOT NULL
);

CREATE TABLE llm_repair_attempts (
  id          TEXT(26) PRIMARY KEY,
  call_id     TEXT(26) NOT NULL REFERENCES llm_calls(id),
  attempt_no  INTEGER NOT NULL,
  error_kind  TEXT NOT NULL,               -- not_json|wrong_type|truncated|missing_field|extra_field
  accepted    INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE llm_routing (
  id           TEXT(26) PRIMARY KEY,
  call_id      TEXT(26),
  requested    TEXT,
  selected     TEXT NOT NULL,
  reason       TEXT NOT NULL,              -- cheapest_meets_requirement|pinned|fallback|budget_exhausted
  cost_micros  INTEGER NOT NULL DEFAULT 0,
  created_ulid TEXT(26) NOT NULL
);
```

## 5. Public interfaces (Rust traits/types, CLI, plugin.toml)

```rust
// src/client.rs
#[async_trait::async_trait]
pub trait LlmClient: Send + Sync {
    async fn complete(&self, req: LlmRequest) -> Result<LlmResponse, LlmError>;
}

pub enum Purpose { Interpret, Plan, Extract, Critique, Summarize, CodeReview, Classify, Diagnose }

pub enum CacheMode { Use, Bypass, Refresh, Replay }

pub struct LlmRequest {
    pub purpose: Purpose,
    pub model: Option<String>,        // None => routing chooses
    pub messages: Vec<Message>,
    pub schema: Option<SchemaId>,     // Some => structured output enforced
    pub max_tokens: u32,
    pub temperature: f32,
    pub cache: CacheMode,
    pub trace_id: Option<ulid::Ulid>,
}

pub struct LlmResponse {
    pub call_id: ulid::Ulid,
    pub text: String,
    pub model: String,
    pub usage: Usage,
    pub cached: bool,
    pub schema_valid: bool,
}

pub struct Usage { pub tokens_in: u32, pub tokens_out: u32, pub cost_micros: i64, pub latency_ms: u32 }

// src/schema.rs
pub trait StructuredOut: serde::de::DeserializeOwned + Send {
    fn schema_id() -> SchemaId;
    fn schema() -> serde_json::Value;          // strict JSON Schema
}
pub trait SchemaRegistry {
    fn register(&mut self, id: SchemaId, schema: serde_json::Value);
    fn get(&self, id: &SchemaId) -> Option<&serde_json::Value>;
    fn validate(&self, id: &SchemaId, raw: &str) -> Result<(), SchemaError>;
}

// src/routing.rs
pub trait Router: Send + Sync {
    fn choose(&self, req: &RoutingRequest) -> RoutingDecision;
}
pub struct RoutingRequest { pub purpose: Purpose, pub complexity: Complexity, pub stakes: Stakes,
                            pub required_precision: Precision, pub latency_budget_ms: u32,
                            pub cost_budget_micros: i64, pub pinned_model: Option<String> }
pub struct RoutingDecision { pub model: String, pub reason: RoutingReason }
pub struct ThresholdRouter { /* deterministic cost/latency/complexity thresholds */ }
// Phase 9 plugs in DecisionCoreRouter implementing the same trait.

// src/service.rs
pub struct LlmService { /* pool, graph handle, client, router, cache, schemas, config */ }
impl LlmService {
    pub fn new(cfg: LlmConfig, pool: sqlx::SqlitePool, graph: GraphHandle) -> Result<Self, LlmError>;
    pub async fn call(&self, req: LlmRequest) -> Result<LlmResponse, LlmError>;
    pub async fn call_structured<T: StructuredOut>(&self, req: LlmRequest)
        -> Result<(T, LlmResponse), LlmError>;
    pub async fn stats(&self, window: StatsWindow) -> Result<LlmStats, LlmError>;
}

// src/accounting.rs
pub struct CallAccount { pub call_id: ulid::Ulid, pub trace_id: Option<ulid::Ulid>,
    pub purpose: Purpose, pub provider: String, pub model: String, pub prompt_hash: String,
    pub schema_id: Option<SchemaId>, pub schema_ok: bool, pub cached: bool,
    pub tokens_in: u32, pub tokens_out: u32, pub cost_micros: i64, pub latency_ms: u32,
    pub status: CallStatus, pub error_kind: Option<String> }
```

## 7. Step-by-step implementation tasks

1. **Vendor copy.** Copy `kg-llm` (and the agentstream/llm-interface patterns) into `vendor/…`; add
   `COPYING.md` files; add the vendored crates to the workspace members. *Check:* `cargo build -p kg-llm`
   equivalent builds inside the workspace.
2. **Crate skeleton + config.** Create `crates/mm-llm` with `#![forbid(unsafe_code)]`; implement
   `config.rs` (`LlmConfig`, `ModelSpec { input_cost_micros_per_1k, output_cost_micros_per_1k,
   typical_latency_ms, context_window, complexity_ceiling }`, `RoutingConfig`) loaded from
   `config/llm.toml` + env. *Check:* unit test loads config with no env and with env set.
3. **Client trait + types + errors.** Implement `client.rs` and `error.rs`
   (`LlmError::{ProviderNotConfigured, Transport, Timeout, SchemaRejected, CacheMiss, Io, Db}`).
4. **Accounting + migration.** Implement `accounting.rs`; add `migrations/0003_llm.sql`; persist a
   `CallAccount` in the same event-log transaction as its call. *Check:* a call writes exactly one
   `llm_calls` row and one audit event.
5. **Mock client.** Implement `mock.rs`: deterministic responses from fixtures and scripted sequences,
   deliberately able to emit malformed payloads. *Check:* mock never touches the network.
6. **Request hash + cache.** Canonicalize `(provider, model, purpose, messages, schema_id, max_tokens,
   temperature)` and hash with sha256; implement `cached.rs` and `llm_cache_index`. *Check:* property
   test — the same logical request always yields the same `prompt_hash`; reordering unrelated fields does
   not change it.
7. **OpenAI-compatible adapter.** Implement `openai.rs` using the vendored `kg-llm` OpenAI client; read
   endpoint/API key from env only; bounded concurrency, bounded retries, timeout. *Check:* constructing
   without env returns `ProviderNotConfigured`.
8. **Structured output.** Implement `schema.rs` and wire it into `LlmService::call_structured`: validate
   raw provider output against the registered strict schema; on failure, **reject** (never coerce), record
   an `llm_repair_attempts` row, and either run a bounded repair pass or return `SchemaRejected`.
   *Check:* `tests/schema_reject.rs` — every malformed fixture is rejected.
9. **Routing.** Implement `routing.rs` (`ThresholdRouter`): choose the cheapest model meeting a declared
   requirement; record `llm_routing`; support `pinned_model` and `budget_exhausted` fallback. Leave the
   `Router` trait as the seam for Phase 9's `DecisionCoreRouter`. *Check:* `tests/routing.rs` golden table.
10. **Replay.** Implement `replay.rs`: `ReplayLlmClient` reads a recorded session artifact
    (`bench/llm/sessions/…/{request.jsonl,response.jsonl}`) and returns recorded responses keyed by
    `prompt_hash`; wrap the live client in a `NetworkGuard` that hard-errors on any outbound attempt.
    *Check:* replay of a recorded session returns byte-identical outputs and triggers the guard zero times.
11. **Service facade + provenance.** Implement `service.rs` and `provenance.rs`: emit one `mm:LlmCall`
    node into `/provenance` per call, linked to `trace_id`; integrate with `mm-core::Id`.
12. **CLI.** Add `mm-cli llm {stats, replay, verify-cache, schema-reject, routes}` with machine-readable
    `--json` output.
13. **Adversarial fixtures.** Author `bench/llm/malformed/*` and a recorded session; commit them.
14. **Redaction.** Implement `redact.rs`: never log API keys or raw message content; log `prompt_hash` and
    length-bounded, optionally hashed excerpts. *Check:* redaction suite (shared with `mm-log`).
15. **Registration.** Run `mm-codex scan` so `mm-llm` and the vendored crates appear with stable URIs,
    owning phase 3, capabilities, and tests.

## 8. Detailed logging requirements

All records are emitted through `mm-log` with the global fields (`ts`, `level`, `target`, `event`, `msg`,
`trace_id`, `span_id`) and carry `call_id` and `purpose` wherever a call is involved. Event codes for this
phase (per parent plan §10 Phase 3):

| Event code | Level | Required fields |
|---|---|---|
| `llm.request` | INFO | `call_id`, `purpose`, `provider`, `model`, `prompt_hash`, `schema_id`, `cache_mode`, `trace_id` |
| `llm.route.select` | INFO | `requested_model`, `selected_model`, `reason`, `cost_budget_micros`, `latency_budget_ms` |
| `llm.cache.hit` / `llm.cache.miss` | DEBUG | `call_id`, `prompt_hash`, `model`, `schema_id` |
| `llm.response` | INFO | `call_id`, `tokens_in`, `tokens_out`, `cost_micros`, `latency_ms`, `cached`, `status` |
| `llm.schema.reject` | WARN | `call_id`, `schema_id`, `error_kind`, `raw_len` (never raw content) |
| `llm.repair.attempt` | INFO | `call_id`, `attempt_no`, `error_kind`, `accepted` |
| `llm.replay.start` / `llm.replay.end` | INFO | `session_id`, `records`, `provider_calls` (must be 0) |
| `llm.accounting.commit` | DEBUG | `call_id`, `trace_id`, `row_written` |
| `llm.error` | ERROR | `call_id`, `error_kind`, full cause chain; **never** the API key or raw prompt |

`mm-cli logs verify` must confirm that every committed `llm_calls` row has a matching audit record and
that `llm.replay.end.provider_calls == 0` for replay runs.

## 9. Testing plan

- **Unit:** config loading (no env / partial env / full env); `LlmError` causes; `ModelSpec` cost math;
  `Purpose` serialization.
- **Property (`proptest`):** request-hash stability and collision sanity; replay equivalence
  (recorded response in ⇒ identical response out); accounting conservation (`tokens_in/out` and
  `cost_micros` never negative; sums equal per-call rows).
- **Golden / replay (`insta`):** routing decision table; a recorded session replays byte-identically.
- **Adversarial:** `bench/llm/malformed/*` never crash, never produce a typed value, and produce exactly
  one `llm.schema.reject` each.
- **Zero-network:** replay and mock runs are executed under `NetworkGuard`; any outbound socket attempt
  fails the test.
- **Concurrency:** N bounded parallel calls preserve accounting (no lost or duplicated rows); the pool and
  graph actor remain consistent.
- **Redaction:** the shared secret-pattern suite finds no key/token in any sink.
- **Integration (`tests/e2e`):** `mm-cli llm stats` reconciles with `llm_calls`; `verify-cache` re-hashes
  every cache entry.

## 10. Pass gate

Run as plain commands; all must exit 0 and satisfy the stated criteria.

```bash
cargo build --workspace
cargo clippy -p mm-llm --all-targets -- -D warnings
cargo test -p mm-llm
cargo test -p mm-llm --test schema_reject --test cache_replay --test routing --test accounting
cargo run -p mm-cli -- llm schema-reject --fixtures bench/llm/malformed/ --assert-all-rejected
cargo run -p mm-cli -- llm replay --session bench/llm/sessions/recorded-session-01 --assert-zero-calls
cargo run -p mm-cli -- llm verify-cache --strict
cargo run -p mm-cli -- llm stats --assert-complete --json
cargo run -p mm-cli -- logs verify
```

Objective pass criteria:

- **Zero provider calls on replay:** `llm replay --assert-zero-calls` reports `provider_calls == 0` and
  byte-identical outputs; any outbound attempt is a hard failure (NetworkGuard).
- **100% schema-violation rejection:** `llm schema-reject --assert-all-rejected` rejects every fixture,
  records one repair attempt each, and produces no typed value.
- **Complete accounting:** every LLM call has exactly one `llm_calls` row with non-null `purpose`,
  `model`, `prompt_hash`, `tokens_in`, `tokens_out`, `cost_micros`, `latency_ms`, `status`; totals
  reconcile with `llm stats`.
- **Deterministic routing:** on the committed labeled toy workload, `ThresholdRouter` selects the cheapest
  model meeting each requirement, and repeated runs are identical (golden test).
- **Logging:** `mm-cli logs verify` passes (schema, audit completeness, ULID correlation, redaction).
- Workspace builds with **zero warnings**; `mm-codex verify` remains green after `scan`.

## 11. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Provider output drifts from the schema | Strict validation + bounded repair + explicit `SchemaRejected`; never coerce |
| Nondeterministic tests | Mock/cached/replay clients are the default in tests; live calls are opt-in via env |
| Cost/latency runaway | `CallAccount` + budgets; routing picks the cheapest sufficient model; `budget_exhausted` fallback |
| Secrets in logs | `Redactor` + prompt hashing; redaction suite in every sink |
| Vendored `kg-llm` drift from upstream | `mmc:copiedFrom` pins revision; re-copy is a reviewed change-set (Phase 11) |
| Hard-coded endpoint sneaks in | Config comes from env only; a test asserts no `http(s)://` literal in `mm-llm` source |
| Cache poisoning / stale responses | Cache keyed by full canonical request hash incl. model + schema; `--strict` re-hashes entries |
